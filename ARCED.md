# ARCED fork notes

ARCEDians Vault for Android: the Bitwarden Android app, rebranded and preset to
`https://vault.arced.foundation` (Vaultwarden). Installed as an APK from
`https://vault.arced.foundation/get`, not from a store.

## Pinned versions

| Component        | Version                                         |
| ---------------- | ----------------------------------------------- |
| Upstream tag     | `v2026.9.1-bwpm` (bitwarden/android)            |
| App version      | `gradle/libs.versions.toml` (`appVersionName`)  |
| Vaultwarden      | `1.37.3` (server, in ARCED_Password_Manager)    |
| JDK (build)      | 21 (Android Studio's bundled JBR works)         |
| Minimum Android  | 10 (API 29), same as upstream                   |

Only the F-Droid flavour is built (`fdroidRelease`): no Firebase, Play Services, push relay
or Play billing. The vault syncs on unlock and on pull-to-refresh, which is on by default.

## Signing

- Application ID: `foundation.arced.vault` (permanent: a different ID is a different app).
- Release key: alias `arced-vault`, RSA 4096, valid until 2059.
- Certificate SHA-256:
  `4B:61:61:38:74:3F:71:7B:19:92:E3:D5:CA:EB:1D:C8:EE:40:9E:C1:31:9E:5A:B8:74:42:18:A1:F3:A1:DE:37`
- Stored as the Actions secrets `ARCED_KEYSTORE_BASE64`, `ARCED_KEYSTORE_PASSWORD` and
  `ARCED_KEY_ALIAS`, plus an offline USB copy (keystore and password) kept with the server backup
  key. Never commit it. If the key is lost, no update can install over existing installs: every
  user would have to uninstall (losing local data) and install a new app.
- CI refuses to publish an APK signed with any other key.

## Release steps

1. Bump `appVersionName` and `appVersionCode` in `gradle/libs.versions.toml`.
   Name: `<upstream version>-arced.<n>`, e.g. `2026.9.1-arced.2`.
   Code: `YYYY·MM·P·NN` from that name, e.g. `2026.9.1-arced.2` → `202609102`. It must go up
   every release, or the update check and Android's installer ignore the new APK.
2. Commit, push `main`, then tag: `git tag v2026.9.1-arced.2 && git push origin v2026.9.1-arced.2`.
3. `.github/workflows/arced-android.yml` builds and signs the APK and force-pushes
   `ARCEDians-Vault-<version>.apk` and `latest.json` to the orphan branch `android-dist`.
4. The server's deploy workflow (ARCED_Password_Manager) unpacks `android-dist` into
   `/get/download/android/`. Installed apps see the new `versionCode` on next start and offer the
   download.

## Upstream update (monthly)

1. Pick the newest `vYYYY.M.P-bwpm` tag that Vaultwarden supports (check Vaultwarden release notes
   and open issues mentioning Android).
2. `git fetch upstream tag vX.Y.Z-bwpm --no-tags && git merge vX.Y.Z-bwpm`.
3. `git rm` anything that reappears under `.github/workflows/` (except `arced-android.yml`),
   `.github/CODEOWNERS` and `.github/ISSUE_TEMPLATE/`.
4. Re-run `node arced/rebrand-strings.mjs` (new strings) and `node arced/render-icons.mjs`
   (if upstream touched the icons).
5. Re-check every file in "Fork changes" below; resolve `libs.versions.toml` to our version.
6. Build, run the test list in `docs/ARCED-DEVELOPING.md`, then release as above.

## Open issues

- **Help links.** "Help center", "Learn more" and the privacy policy still open bitwarden.com, as in
  the extension (decided 2026-11-02 for the extension: those pages document the same features).
- **Callback scheme.** WebAuthn, Duo and SSO callbacks use the `bitwarden://` scheme, which the web
  vault's connector pages expect. If the official Bitwarden app is installed too, Android may ask
  which app to open after a WebAuthn 2FA prompt; pick ARCEDians Vault.
- **Bitwarden SDK licence.** The app links `com.bitwarden:sdk-android` from Bitwarden's GitHub
  Packages registry, the same binary the upstream F-Droid build uses. It is under Bitwarden's SDK
  licence, not GPL; check it before any wider (store) distribution.
- **Sideloading verification.** Google's developer verification for sideloaded apps (rolling out
  2026–2027) may require registering ARCED in the Android developer console with this signing key.
  Check the status for Bangladesh before each release.
- **Unit tests.** Upstream's unit tests are not run in CI; some will fail on ARCED strings and
  defaults (for example the default environment).
- **Rebrand leftovers.** Premium and Authenticator upsell screens, the beta icons, and in-app
  illustrations keep Bitwarden's artwork (in ARCED colours).
